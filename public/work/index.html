Truth debt

defects on production today
critical

Vegas portal force-redirects — the opposite of the WS6 spec

/vegas/ is a 4-stage "trapdoor": fake city shell (~950ms, badged Now Live · #9) → cinematic fall → crossfade into the exact dimmed photo SlotGenie's age gate uses → location.replace('https://slotgenie.bet'). Plus a hidden pre-warming iframe. No tap-through, no choice, zero UTM attribution. The brief mandates "No auto-redirect — the traveler chooses."

fix in WS6 — keep the animation language, add chosen tap-through + UTM + portal_slotgenie_click beacon
critical

Service worker pins users to stale data forever

CACHE_NAME = "localtour-directory-v1" — static, never versioned — with cache-first for everything and every GET written back. HTML and data.js stay frozen at first visit. Unacceptable for a product selling fresh deals.

fix in WS2 — build-hash cache name, network-first for HTML + data.json
high

All 8 per-city stats drift — rigged to sum correctly

explore.html business counts: NYC shows 312 (actual 190), Houston 142 (actual 212), Smoky 74 (actual 155), LA 218 (actual 154)… every city wrong, yet the shown values sum to exactly 1,471. Same pattern on concierge.html node counts (sum to exactly 214). The brief flagged 3 cities; it's all 8, twice over.

fix in WS2 — every displayed number computed from data at build time; verify script fails on drift
high

Expired events render — 53 of 94 hard-dated events are past

56% of ISO-dated events are already over (vs 2026-07-04). Confirmed FIFA bug: LA (2026-06-12) and SF (2026-06-11) encode the World Cup as single past dates — reading as expired while the tournament is still running — where NYC correctly uses the range 2026-06-13 to 2026-07-19. The other 118 events are recurring free-text ("recurring: mid-July") — evergreen but unsortable.

fix in WS2 — date-filter at render; verify script fails a city with <3 upcoming events
high

Partners page promises what doesn't exist

"Conversion analytics baked in" — nothing behind it. No tier names, no prices, no pricing.json anywhere. Creator track promises "server-side tracking, real-time analytics, CSV export" — none exists. All five CTAs are mailto: links. Zero fetch calls, zero forms, zero payment integration in the whole product.

fix in WS3+WS4 — beacon + merchant stats make the claim true before the copy survives
medium

Category taxonomy drift across cities

Chicago uses a legacy short taxonomy (bars, coffee, outdoor, wellness) vs the standard (bars_nightlife, coffee_bakeries…). Miami keeps legacy wellness and adds boating_water; SF adds boating_water too. Cross-city filtering would break today. Also: LA uses "" where 7 cities use null; ratings are strings everywhere; deal fields ex/rv are 100% unused.

fix in phase 0 — normalize during data.js → data.json migration, document in DATA_SCHEMA.md
medium

3 deals already expired · copy contradictions

Joe's Stone Crab Takeout (exp 05-15), SFMOMA (04-17), SF Restaurant Week (04-19) still render. about.html says "one of seventeen," then "seventeen more," then "the other sixteen" — three different subsidiary counts on one page. Landing hand-types 8 / 1,471 / 0 (currently correct, but literals).

fix in WS2 — respect exp; copy audit line by line
